# Edit Task Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user edit every field of an existing task from the row's "…" menu, saved in one request.

**Architecture:** Additive endpoint `PATCH /api/tasks/:id/details` validated by a new shared Zod schema; the client
reuses `TaskForm` inside a new edit side panel opened from `RowMenu`.

**Tech Stack:** Zod 4, Express 5, Mongoose 9, Vitest + Supertest, React 19, TanStack Query 5, shadcn Sheet.

**Spec:** `docs/superpowers/specs/2026-11-20-edit-task-design.md`

## Global Constraints
- The v1 tests and `PATCH /api/tasks/:id` stay unmodified; all 120 existing tests keep passing.
- Error body: `{ message, errors?: [{ field, message }] }`. No `any`, no escaping `as` casts.
- Title 3–100 chars, description ≤ 500 chars (existing `TITLE_MIN/MAX`, `DESCRIPTION_MAX`).

## Review Focus
- Editing a task whose assignee was later deactivated, without touching the assignee → 200, not 400.
- Clearing the description (`""`) → description removed from the response.
- Changing status away from / to `done` → `completedAt` cleared / set, as in v1 PATCH.
- Unknown key in the body (`{ foo: 1 }`) or empty body `{}` → 400.
- Malformed id (`abc`) → 404.
